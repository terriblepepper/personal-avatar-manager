# 操作手册

部署与维护说明，按 2026-11-09 源码整理。用户操作见[用户手册](用户操作手册-purge.md)。示例地址须替换为实际部署；不包含运行账号或私钥。

## 安装与服务

推荐 Linux、Python 3.13，兼容 3.12。项目统一 `.venv` 与根目录 `uv.lock`；EverOS 不单独建环境。

```bash
uv sync --locked
./service.sh install
systemctl --user status personal-avatar.service
journalctl --user -u personal-avatar.service -n 80 --no-pager
curl -fsS "${AVATAR_PUBLIC_URL:-http://127.0.0.1:${AVATAR_PORT:-18080}}/api/health"
```

源码默认数据目录 `data/`。安装包默认使用 XDG 数据目录，可用 `AVATAR_DATA_DIR` 或 CLI `--data-dir` 指定。源码启动脚本会加载项目 `.env`，安装包 CLI 只读取进程环境。首次根管理员密码在数据目录 `initial-admin.txt`；配置、密码、保险库主密钥和身份材料仅允许属主访问。

`service.sh start` / `service.sh stop` 支持本地启动，已安装用户服务时使用 systemd。生产默认端口 18080，Web 用户和管理入口分别为 `/`、`/admin`。健康检查不依赖是否开放 API 文档。

## Keycloak 与权限

在私有 .env 中填写实际身份服务和客户端。示例配置如下。

```dotenv
AVATAR_OIDC_ENABLED=1
AVATAR_OIDC_ISSUER=https://id.example.org/realms/example
AVATAR_OIDC_CLIENT_ID=example-client
AVATAR_PUBLIC_URL=https://你的平台域名
AVATAR_SECURE_COOKIE=1
```

回调地址须与 Keycloak 客户端登记一致。公开客户端无需 Secret；机密客户端的 Secret 仅通过服务器私有配置传入。根管理员保留本地入口；普通账户按 issuer/sub 绑定，不能用手机号、学号、工号或相同用户名自动合并。

管理员可在账户迁移界面核验后重新绑定。服务器离线工具使用明确 issuer：

```bash
.venv/bin/python scripts/manage_accounts.py bind-oidc 用户名 Keycloak-User-ID --issuer "$AVATAR_OIDC_ISSUER" --data-dir /绝对路径/data
```

`manage_accounts.py create-admin` 创建本地管理员需交互输入密码；开启 OIDC 后，非根管理员也要完成统一认证绑定。权限以数据库实时角色为准；列表记录删除不改变审核决定或实体归属。

## 正式注册、证书与端口

本地 Demo 仅用于隔离开发验证。新个人分身生产模式为 `AVATAR_PROVIDER=acps-direct`，不再申请个人本体后派生。管理系统使用自身 integrated 实体；Registry 账号与 Keycloak 账号是不同凭据。

```dotenv
AVATAR_PROVIDER=acps-direct
AVATAR_SYSTEM_ATR_ENABLED=1
AVATAR_SYSTEM_ATR_POLL_INTERVAL=3600
AVATAR_SYSTEM_AIP_ENABLED=1
AVATAR_SYSTEM_AIP_PORT=10000
AVATAR_SYSTEM_AIP_PUBLIC_URL=https://服务器IP:10000/aip/rpc
AVATAR_ENTITY_AIP_ENABLED=1
AVATAR_ENTITY_AIP_PORT=10001
AVATAR_ENTITY_AIP_PORT_END=15000
AVATAR_PERSONAL_ATR_ENABLED=0
```

先按实际部署配置 Registry、CA 与信任链，再启用注册；敏感凭据只写私有环境。管理身份模板可用 `scripts/init_system_identity.py --kind management --help` 查看参数。正式个人候选由已审核资料生成，平台审批后提交 Registry，等待 Registry 管理员审批、签证和监听就绪。

每个内部账户固定分配独占端口，IP SAN 必须覆盖 ACS 中地址。改名、重新签证和换 AIC 不重新分配端口；10000 不得进入个人端口段。未完成的 Registry 审核和证书获取每小时尝试，管理员可手动刷新。注册签证成功后管理台显示“已部署”。只有注册、审核/ACS 获取、证书签发/更新及注销撤销使用远端注册基础设施；日常分身通信和 Health 不查询 Registry 或 CA。

TLS 装载和实际通信读取加锁的本地 active ATR 材料，校验 ACS/证书指纹、AIC、密钥、有效期、签名链与端点绑定；本地撤销或注销立即按状态拒绝，材料变化时重新装载。运行时不查询远端最新吊销状态，因此其他系统在远端新撤销的证书不会即时同步到本地。端点启动失败后等待手动 Health，不再每分钟自动重试；新增或替换分身只重建受影响的端点。

Health 直接向该分身 ACS URL 发起真实 mTLS ACPS 请求，使用标准只读 get-task 和随机的不存在任务标识，以经过身份认证的任务不存在响应确认端点存活；不创建任务、不调用模型、不查询注册基础设施。当前 WIT 未公开独立 health/ping RPC，不能把本地端口监听或注册服务器响应冒充该分身健康。检查结果包含时间，失败保留部署记录；它只代表平台服务器到该 URL 的探测结果，不代表所有外部客户端网络都可达。

上线 ACS 不原地修改；用户显式修改并通过平台审核后，等待活跃租约排空，注销旧身份并撤销旧证书，再以同一端口重新申请，期间离线且 AIC 改变。界面分别展示 Registry、签证及协议就绪状态。

离线运维的状态核对使用明确配置，不能对响应不确定的申请盲目重提：

```bash
.venv/bin/python scripts/wit_identity.py status --config /绝对路径/registration.json
.venv/bin/python scripts/wit_identity.py reconcile --config /绝对路径/registration.json --usage client --registration-id 已核实申请ID
```

旧派生身份仅保留迁移兼容，不是新用户正常创建流程。身份维护前先停服务、备份并核对执行范围，以现有维护命令的 `--help` 为准。

## 数据、原件与备份

资料库总额度 10 GiB，Soul 直接上传 10 GiB；资料库导入 Soul 不计后者额度。普通文件按剩余总空间接收，HTML 网页与动画单件最多 100 MiB。会话工作区不设文件数量和存储总量配额，已到期的原件与预览定期清理。目录说明、权限和索引清单均在业务主库，原件与派生存储位于同一私有数据根目录。

升级前停止应用写入，保持 PostgreSQL 在线并导出逻辑备份。同时归档 `.env`、保险库 `model-secrets.key`、资料/聊天/Soul 原件、EverOS 记忆文件、正式 ACS、证书、私钥和 ATR 状态。旧版升级还需冻结并导入本地存储，见[迁移与恢复](PostgreSQL运行.md)。

恢复后检查文件权限、数据库外键、原件可读性、健康接口、固定端口、CA 和在线状态。启动增量迁移不应改写历史归属；不要在运行中的正式数据库上手工执行 initialize、测试或批量清理。记录清理仅隐藏展示或删除可删除历史，保留必要业务/费用审计。

## 解析工具与模型

DOC/DOCX 正文与内嵌图表需要 LibreOffice，文档图片还涉及 Poppler；OCR 使用 Tesseract 和中文/英文语言包。音视频使用 ffmpeg/ffprobe。可在系统安装，或按项目工具安装到统一虚拟环境：

```bash
.venv/bin/python scripts/install_runtime.py office
.venv/bin/python scripts/install_runtime.py ocr
```

缺失依赖时明确报告或标记不完整，不在请求中自动安装。模型和嵌入能力优先采用服务端目录/证据，已确认时锁定；能力未确认时可手动纠正图片输入，聊天还支持纠正音频输入。纠正随配置保存，后续明确的目录证据优先。勾选只声明期望使用的能力，不保证上游实际支持；保存时的小规模文本校验不验证全部多模态输入。模型 Key 加密存储，不进入日志或子进程环境。模型网络使用受控 HTTPS、公网解析、代理规则及有界响应。

点击保存模型或嵌入配置时，先用待保存的地址、模型和 Key 发起小规模实际调用（聊天短回答或单条嵌入），最多等待 45 秒。校验失败时保留旧配置、保存日期和 RAG 索引；成功后才原子提交并按需更新索引。校验期间配置被其他页面修改会要求刷新后重试。模型列表接口不是可用性依据；验证会产生少量上游用量，不写入聊天历史。

DeepSeek 等预设平台使用服务器维护的固定官方 API 地址，聊天与嵌入配置中均不可编辑；后端拒绝提交其他地址。只有选择“自定义平台 / 网关”才能填写不同根地址，自定义服务支持 HTTP 和 HTTPS，无需 IP 白名单；更换 IP 后直接填写新地址并保存校验。

资料/Soul 文件索引共享每账户最多 10 路工作槽。临时索引 HTTP 故障最多额外重试三次，认证、余额、格式、取消及重启中断不自动重放收费请求。详见[RAG](资料RAG与嵌入.md)与[Soul](知识库与soul.md)。

## 小镇与故障排查

小镇个人问答支持 start/continue/get/complete/cancel；慢请求先返回 working，由调用者查询原任务。连接断开不自动重发或取消，只有明确取消命令才终止工作。管理服务的查询技能返回实际结果，需要网页的技能返回 URL；不要将个人 RPC 配成 Web URL。

网页聊天使用独立提交和查询：`POST /api/chat/generations` 持久化请求后返回 202，服务器常驻 worker 独立生成并保存回答；浏览器通过 `GET /api/chat/generations/{request_id}` 查询原请求；`/api/chat/pending?conversation_id=…` 保留为恢复会话最近任务的兼容入口。刷新、关闭页面或平板浏览器切入后台不参与生成任务的生命周期，恢复连接后读取已保存的回答或进度。提交响应丢失时按请求标识确认接收结果，不自动重发；只有原请求实际失败才显示失败原因。分身间会话同样由服务器继续执行，回到前台立即更新状态。服务重启会继续处理排队请求。已开始的个人会话先核对检查点、写入者和原授权，安全的决策或写作阶段可接续，用户主动暂停的任务等待用户继续。无法确认外部操作结果时保留未确认状态。重复同一请求 ID 可查询原任务。

`chat_generation_jobs` 保存独立请求账本及提交授权快照，`chat_pending` 仅为兼容投影。任务状态为 queued/running/succeeded/failed/cancelled/indeterminate/awaiting_input；回答历史、来源和成功终态同事务发布。清空会话会清除任务内容并保留最小去重凭据；不要手工删除活动账本。排队期间修改模型配置会使旧请求失败并要求重新提交，新增技能或文件授权不会扩大旧任务权限，撤销仍生效。

分身 ACPS 接收端先返回 working，再由应用持有的后台任务生成；发送端使用 get 查询原任务，不重新发送 start/continue。服务重启后先核对原任务、发言人和回执。已接收的远端任务按原 ID 查询；个人协议在通过鉴权的 get 中可接管安全断点。结果不明的外部操作需核对后再处理。

- **网页登录循环**：核对 public URL、代理 HTTPS、Cookie secure 设置、Keycloak 回调及会话续期；不要简单关闭鉴权。
- **分身不在线**：检查身份阶段、证书有效期/IP SAN、CA 状态、端口冲突与监听。正式身份数不是在线数。
- **Registry/CA 认证或限流**：查看脱敏日志和重试时机；遵守 Retry-After，不反复重申证书。
- **小镇追问未确认**：核对 continue/get/cancel 的时序、结果 ID 和连接错误，区别结果已生成与客户端已收到。
- **资料未解析或学习失败**：检查所需模型输入能力、工具支持、输出预算、解析工具和进度，不把元数据索引误作全文读取。

只读健康验证和隔离测试不会发送真实模型请求；真实模型、Registry 或小镇消息诊断须单独确认其费用和外部影响。

## 用户存储布局

用户私有文件统一位于 `data/users/<稳定内部用户ID>/`，包含 `attachments`、`chat_attachments`、`knowledge`、`everos`、`skills`、`identity`（ACS/证书）。不使用会过期的 Access Token 作目录名。启动时先迁移旧目录，冲突立即停止，不覆盖文件；无法确认归属的旧文件保留在 `maintenance/unowned-storage`。 会话文件按会话 ID 存放在 `chat_attachments/` 下。涉及此布局变更的升级与回退需使用对应版本的数据库及私有文件备份。

业务主库中的会话、聊天、Soul 版本及资料关系仍以 user_id 隔离，保留共享数据库以支持事务、跨分身任务和审计；主密钥、系统身份、平台配置也保持共享。升级须先停止服务并备份。

## 成套备份操作

以下示例针对源码默认 `data/`，备份保存在项目外。自定义 `AVATAR_DATA_DIR` 时必须改为实际路径，不能仅备份空的默认目录。备份包含账号、原件、会话、主密钥及证书，访问权限应与生产数据相同。

1. 确认聊天、索引及 Soul 构建已结束，停止应用写入。保持 PostgreSQL 在线。
2. 用 `pg_dump` 导出 PostgreSQL 主库（含向量、队列和协议账本）。迁移旧版时另外保留完整冻结的旧存储，操作见[PostgreSQL 运行](PostgreSQL运行.md)。
3. 将同批私有数据目录与 `.env` 归档至受保护的项目外目录。逻辑备份时从文件归档排除在线 PostgreSQL 数据目录。核对归档内容和校验和，在隔离环境试恢复后启动应用。

## 恢复与版本回退

只使用可信的完整备份。数据库、`model-secrets.key` 和用户原件必须来自同一次备份；单独恢复数据库可能产生文件缺失，单独恢复主密钥可能使已保存的模型 Key 无法解密。

1. 停止服务，核对备份校验和并列出归档内容。
2. 在项目外保存当前私有文件和数据库快照，保留回退现场；恢复到隔离的私有数据目录和新建空库。
3. 还原私有文件、`.env` 和匹配版本的程序，核对属主和权限。使用 `pg_restore --exit-on-error --single-transaction` 将同批转储恢复到空库，令 `DATABASE_URL` 指向恢复后的库。
4. 运行 `uv sync --locked` 恢复该版本依赖，再启动服务。
5. 检查健康、登录、资料下载、Soul 状态和个人协议端口；确认后再处理旧现场。

恢复时使用备份对应的应用版本和兼容的 PostgreSQL 版本。若目标旧版读取本地数据库，须恢复其迁移前冻结的原始存储。证书和注册身份从同批备份恢复，避免重复申请或改变身份。

## 日常升级步骤

```bash
systemctl --user stop personal-avatar.service
# 按上一节完成备份，然后更新源码；保留 .env 与 data。
uv sync --locked
.venv/bin/python scripts/run_tests.py --jobs 4 unit -q
systemctl --user start personal-avatar.service
curl -fsS "${AVATAR_PUBLIC_URL:-http://127.0.0.1:${AVATAR_PORT:-18080}}/api/health"
systemctl --user status personal-avatar.service
```

正常升级不必重装 systemd 服务；只有项目路径、服务模板或启动方式改变时，再运行 `./service.sh install`。不要开启多个 uvicorn worker 或同时用 systemd、nohup 启动两份平台写同一数据目录。启动失败先看日志，不循环删除文件或反复申请身份。

## 文件、索引和 Soul 的维护

- **新增资料**：资料文件和 Soul 知识库都支持拖拽本地文件或文件夹上传。拖到文件夹行会上传至该文件夹，拖到列表空白处上传至当前目录；保留多级目录及空文件夹，拖拽目标会高亮。也可使用上传按钮选择目录。权限及说明可后续设置，说明选填；容量和解析校验与按钮上传一致。索引后台执行，观察“已完成/剩余”及具体错误。原件和索引是两份不同数据。
- **同步索引**：处理新增、变化、失败或缺失项；健康且配置未变的索引不应重新排队。先用同步排查普通缺漏。
- **重构索引**：显式重新生成缓存代和向量，会调用配置的嵌入/视觉模型，可能计费。模型、维度或解析能力改变时按提示使用，不能当作频繁刷新按钮。
- **上传技能**：暂停使用。个人聊天、分身间消息和任务不加载已安装技能。技能页面只读并保留安装记录。资料文件检索和 Python 沙箱仍按会话权限使用。
- **绘图**：所有对话默认支持图表绘制，不需要在工具菜单开启。模型按用户要求或解释需要直接生成 Mermaid 图表，在气泡中预览，并可切换源码或下载。可通过百分比或加减按钮缩放，超出区域后滚动查看；点击图表图片可打开与文件预览相同的小窗，独立缩放、适应宽度或下载。工具菜单仅保留需要授权的工具，例如 Python 沙箱；旧会话的绘图关闭记录不再生效。
- **模型网络**：模型生成、嵌入、模型列表查询优先直连；配置 `AVATAR_MODEL_PROXY` 后，只有建连失败才尝试备用代理。例如 SSH 转发了本地 HTTP 代理时填写 `http://127.0.0.1:20000`；未配置则只直连，不创建 SSH 连接。证书校验失败、请求写入失败、响应读取超时和 HTTP 错误不切换通道重发，避免重复调用。所有文本与工具生成均以流式请求发送，完整 JSON 网关响应也可读取。建连成功且收到成功响应头后发生断流，每步最多自动重试 5 次。模型可能对多次尝试分别计费。聊天气泡在重试耗尽后提供“重试”和“结束任务”。普通模型请求读取等待 120 秒。SSE 收到有效正文、推理或工具参数分片后，重新计算无进展时限（一般 180 秒，HTML 制作和动画 600 秒）。空心跳不续期。一次模型调用与其重试共用原六次尝试的总等待预算，耗尽后可手动重试或结束。连接超时仍为 10 秒。长步骤在气泡中显示模型进度和断流重试次数；浏览器连续 15 秒未收到任务快照时按原请求编号查询。流式响应分别核算 SSE 传输总量、单帧和有效输出；整段 JSON 响应单独核算。超限提示显示触发项、实收字节和上限，便于区分传输问题与 HTML 文件的 100 MiB 限制。
- **索引失败**：先查模型 Key、余额、维度、格式、代理和解析依赖；临时 HTTP 故障已有额外三次退避。修正配置后再通过网页重试。检查 PostgreSQL 内的发布状态、向量引用和失败原因，保留原件及生效清单。
- **Soul 素材**：资料库导入不占 Soul 直接上传额度。素材和风格学习有单独状态，索引成功不代表 Soul 已更新或审核生效。
- **记忆修订**：手工补充通过页面保存并按流程确认/审核；自动学习以当前 Soul 旁提示为准。不要直接编辑 EverOS 私有文件来绕开生效指针。
- **删除资料**：使用文件管理器或批量操作，让权限、引用、索引和原件一起处理。不要直接删除 `attachments/*.blob` 或把公开文件复制到 Web 静态目录。

## 账号与正式身份的维护入口

首次管理员密码位于实际数据根的 `initial-admin.txt`。已有账户需要调整角色、身份绑定时优先使用管理后台；不要根据相同用户名、学号或工号直接合并账户。离线创建管理员或绑定 Keycloak 前先查看：

```bash
.venv/bin/python scripts/manage_accounts.py create-admin --help
.venv/bin/python scripts/manage_accounts.py bind-oidc --help
.venv/bin/python scripts/manage_entities.py --help
.venv/bin/python scripts/wit_identity.py --help
```

分身审批顺序为平台审核、Registry 审核、签证及协议就绪。未完成的审核和签证每小时尝试，也可由管理员手动刷新。注册签证完成后显示已部署，管理员通过 Health 按钮按需检查；部署记录不代表已经检查外网连通性。修改线上 ACS 会进入草稿审核，发布时注销旧身份重新申请，期间离线且 AIC 改变。

旧存储迁移遇到目标冲突会停止，不能自行覆盖。用户目录固定对应内部 user_id；用户名、Keycloak 绑定、AIC 改变都不需要重命名用户目录。`maintenance/unowned-storage` 是待核对文件，不是已经确认可删的垃圾。

## 运行监控

访问同一平台地址下的 `/ops/`，使用本地管理员账号和密码。启用统一认证的部署沿用仅根管理员可用本地密码的规则。已有本地管理员会话可直接打开。

页面显示近期 HTTP 请求量、并发、4xx/5xx、流量与延迟，可查看近一小时、一天或七天的趋势。请求量和错误按请求结束时计数。流量按应用收发的 HTTP 正文字节计量，普通响应延迟单独统计。热门接口按固定路由模板汇总。长连接提前断开计入中断。

服务面板包括应用进程、PostgreSQL 连接池和锁等待、Redis 与 Kafka 就绪、事务转发积压及任务队列。各服务共享每 15 秒的采样。历史保存完整分钟的汇总数字，保留七天。可暂停自动刷新或手动刷新。排查时对照接口 P95、内部耗时及同一时段的积压变化。

## 日志、空间和端口检查

```bash
journalctl --user -u personal-avatar.service -n 100 --no-pager
journalctl --user -u personal-avatar.service --since '1 hour ago' --no-pager
du -sh data/users data/maintenance dist .venv
ss -ltn
```

systemd 模式主要查看 journal；本地脚本模式查看 `data/server.log`。个人协议的脱敏诊断位于各用户 `identity/` 中；对外提供日志前再次检查是否含个人资料或原文，不发送 `.env`、密码、Token、私钥和完整注册配置。

端口检查中管理协议默认 10000、个人范围 10001～15000；以数据库实际分配和后台状态为准，不要求所有范围端口都监听。端口冲突时检查重复进程和当前占用，不随意改已提交 ACS 中的端口。

空间不足时先转存旧发布包和已确认可清理的备份。测试数据由测试入口清理，维护备份按自己的保留周期处理。不要使用模糊的通配删除命令清理整个 data、证书或用户目录。

## 正式证书续签

后台每 30 分钟检查管理平台和已激活分身的正式证书。剩余有效期不超过 24 小时时自动排队续签客户端与服务端证书。同一分身正在审核、注销或维护时延后检查。签发成功后读回新证书并核对身份；结果不确定时保留原记录供管理员核对，避免重复签发。

所有管理员可在「平台设置 → 环境信息 → 平台证书」查看系统 AIC、签发者、指纹、代次和到期时间，刷新本地状态或立即续签。普通分身证书仍可在分身管理列表手动维护。
