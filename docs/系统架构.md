# 系统架构

平台运行及并发设计更新至 1.4.0。部署操作见[操作手册](操作手册.md)，算法见[RAG](资料RAG与嵌入.md)和[Soul](知识库与soul.md)。

## 状态与缓存

PostgreSQL 记录账户、审核决定、任务状态与 RAG 索引代次。Vue 的 Pinia 保存当前会话和侧栏角标。SSE 在线时，会话状态与首页概览每 60 秒校对，并按账户变更事件立即刷新。断线后每 8 秒轮询。管理侧栏按待审变更刷新计数。

管理员通过数据库鉴权后，待审计数优先读取项目 Redis。缓存有效期 5 秒，资料或 Soul 的提交与审核完成后使计数失效。同一进程的并发未命中合并为一次 SQL 读取，跨进程用 WATCH 防止失效后的旧值回填。Redis 超时、重启或关闭时，接口直接执行与管理概览相同的计数 SQL。页面刷新周期和缓存有效期都会影响角标可见时间，实际审核总是校验数据库里的当前状态。每个部署使用独立 Redis 套接字。

聊天提交以请求 ID 标识同一次指令，历史刷新失败时保留原提交结果。文件草稿带初次编辑的修订号，保存时只提交用户修改的字段。RAG 工作进程按代次续租、发布和回写。租约到期且结果未确认的任务进入失败态，人工重试可避免重复计费。

### 任务队列与实时更新

个人生成、分身协作、索引、Soul 和身份维护在业务事务中将唤醒事件写入 PostgreSQL 事件表，转发进程分批投递到 Kafka。Kafka 记录任务类型，现有 PostgreSQL 账本保存任务、租约、取消、顺序与恢复进度。消费组接收唤醒后由对应 worker 条件认领任务。即使唤醒重复、迟到或丢失，数据库对账仍可发现已受理的任务。

每个页面使用一条 `/api/updates` SSE。Redis 分发收件箱、待审、账户概览和协作状态变更提示。页面按需请求授权快照，重连时立即补读。个人聊天流保留既有 SSE 事件格式。Redis 或监听不可用时客户端恢复轮询，Kafka 不可用时后台恢复原有数据库扫描频率。小镇 ACPs 接口和文件交付沿用现有契约。

## 模块与生命周期


运行时统一装配 PostgreSQL 业务表和模型更新回调。基础设施层不导入业务包。模型设置写入与索引通知在同一事务中提交。SQLite 快照和迁移实现位于 `scripts/migrations/`，由离线迁移命令加载。

Web 入口按账户、资料、聊天、附件、模型和管理职责拆分路由。分身协作分别由会话查询、任务状态、单轮执行和恢复模块负责。Soul 工作区负责素材、草稿和审核，后台构建独立处理排队、调用与发布。分身循环的披露、上下文投影、工具回执和最终交付核验各有独立模块。

| 模块 | 职责 |
| --- | --- |
| `avatar/api` | FastAPI 路由、登录依赖、CSRF 与资源下载 |
| `avatar/accounts`、`profiles` | 账户、Keycloak 绑定、资料、审核及记录投影 |
| `avatar/files` | 原件存储、目录权限、会话引用、通用解析及上传缓冲 |
| `avatar/rag` | 授权检索、父子分块、精确余弦/BM25Plus/RRF、原子发布及原件读取编排 |
| `avatar/conversation` | 聊天入口与记忆；jobs 生成任务、collaboration 分身会话、tools 会话授权 |
| `avatar/knowledge` | 素材、Soul 构建/审核、持续学习及 EverOS 桥 |
| `avatar/protocols` | identity 身份、registration 注册、transport 端点/传输、tasks 协议任务及小镇授权 |
| `avatar/runtime` | WIT 装配、监听器、固定端口及后台生命周期 |
| `avatar/models` | 模型配置、能力证据、受控 HTTPS、缓存及用量 |
| `frontend/src` | Vue 页面与组件、类型化 fetch、会话 Pinia、Router、聊天 SSE 与资源清理 |

`AvatarPlatformComponent` 装配完整平台和各分身运行时；不是每个用户单独安装一份 Web 平台。每个正式分身有独立 AIC、身份材料和监听端口。`serve_http=False` 可由宿主挂载 ASGI，但不能重复进入 lifespan 或让多个实例并发写同一数据目录。

## 会话动画

动画作为 HTML 会话文件交付。前端在禁网的隔离 iframe 中预览，支持本地 Three.js。作品单件最多 100 MiB，复用会话权限、转存和 RAG。

## 身份与授权

业务外键保持稳定内部 `user_id`，统一认证使用 Keycloak `issuer/sub` 唯一绑定。用户名、学号和工号不用于自动接管或合并账户。根管理员的本地入口与普通统一认证分开；管理员权限每次请求从数据库核验。

个人实体通过 `acps-direct` 直接提交 Registry。平台先审核候选，Registry 再审核、签证；只有证书校验和监听器实际就绪才算在线。ACS 发布修改需先等待活跃租约结束，再注销旧身份并重新申请，不能原地改写已签名 ACS。

管理 RPC 固定 10000，个人分身按稳定内部账户分配 10001～15000。`avatar_entity_ports` 持久保存映射，改名、换 AIC、重发证、重启都不重新分配。独占端口使用 IP SAN，不依赖个人 DNS 或 hosts。

分身间 TaskCommand 的 `commandParams.requester` 包含 Keycloak sub/issuer。接收端同时核对 mTLS 对端 AIC、已授权任务双方及绑定，JSON ID 本身不是凭据。小镇无用户令牌时按访客临时会话隔离；显式提交的用户 Token 仍严格核验。Web 管理后台始终保留登录权限。

## 数据与文件

`DATABASE_URL` 指向 PostgreSQL，统一保存资料、审核、任务、历史、引用、RAG 发布与向量，以及 EverOS 队列和向量。原件、身份材料和 EverOS 记忆文件仍按账户存放；保险库主密钥单独保存在数据目录。权限和修订通过事务核对，文件删除有回滚保护。见[数据库部署与恢复](PostgreSQL运行.md)。

资料原件总额度 10 GiB，Soul 直接上传 10 GiB；导入的资料素材不计 Soul 额度。目录权限采用最近显式父级设置，单独设置的文件或子目录形成继承边界。公开访问只暴露授权文件和由这些文件推导的目录，不能遍历他人私密目录。

RAG 索引按内容和配置增量发布，成功缓存可复用；目录筛选用实时业务路径选文件 ID，不要求旧向量包含路径。新版本未完整写入前不作为完整索引发布。同步与强制重构语义分开，查询和回答前复核权限。临时索引 HTTP 故障最多额外重试三次，不把普通聊天发送也变为自动重试。

WIT 3.2.0 提供宿主组件、ATR 身份读取、Direct 扩展接口和报文校验。平台将 `protocols/transport` 下的监听与发送组件接入这些接口，TLS 接入按本地身份选择证书，发送端在传输任务正文前核验受信 CA、端点主机名和目标 AIC。公开访客通过小镇任务入口使用独立的身份与授权范围。

## 会话、任务与记忆

模型适配器将结束原因和工具调用归一化。分身循环只执行完整、通过权限与参数校验的动作。单次输出耗尽时，未完成的正文或作品留在私有草稿，下次从已提交的字节游标续写。批量调用被截断时，整批等待模型重新确认。模型报告输入超窗时，下一次请求会进一步缩小历史视图。

每条新请求由分身当前配置的模型进行工具披露。模型根据用户目标和当前授权目录决定直接回答或选择所需工具。证据充分且无需工具时，可在披露调用提交完整答复。常规决策默认提供当前入口允许的 `ask_user`、`search_materials` 和 `get_current_time`。如果模型选择了当步尚未声明的工具，服务端根据模型响应中的工具名核对当前授权和前置回执，在下一轮补充可执行的工具声明。被拒绝的整批调用均未执行。参数无效、授权不足或前置回执缺失会返回具体原因。完整读取单一会话文本原件并取得回执后可直接进入后续目标。

每一轮推理从原始历史、未完成目标和已核验回执生成工作上下文。已配置的输入压缩阈值与输出预留分别核算。单次生成耗尽输出预算且没有可见片段时，草稿恢复轮在提供商支持的范围内降低推理消耗，普通对话继续使用用户选定的强度。历史摘要绑定到对应的前缀，本轮过长的工具输出单独处理。模型保留可复查的回执引用，按需取回细节。个人会话、分身间任务和协议入口分别绑定执行者和资料权限。成功结果与对外可见回执按入口事务提交。协作的 ACPS 查询、断点恢复和最终交付共用答复回执核验，检查正文摘要、当前授权和原件读取凭证。

聊天输入按 64 KiB UTF-8 校验。进入分身循环后，规划、验收条件和查询的合计文本预算可随模型可用输入窗口扩大。作品按成品总大小校验，最大 100 MiB；模型每次调用仍使用配置的上下文和输出上限。

### 长任务的上下文和恢复

| 运行条件 | 平台动作及保留的信息 |
| --- | --- |
| 请求尚有空间 | 按当前模型窗口核算系统说明、工具定义、历史、目标与回执。保留能容纳的原文，并预留配置的单次输出额度。 |
| 达到压缩比例，或下一次请求将装不下 | 在发起下一次模型调用前整理早期历史和当前回合前缀。保留用户要求及补充、开放目标、验收条件、证据来源、失败和待执行动作。配置 60% 时，分身在 55% 检查；物理窗口可更早要求压缩。 |
| 单份回执或一个文件很大 | 持久回执保留全文。模型读工作摘要后，可按编号、文件 ID 或游标取回细节。读取旧作品时校验当前身份、会话、有效期和内容摘要。 |
| 单次输出用完 | 接到有效输出就保存已确认片段及 UTF-8 游标，下轮从该处续写。工具参数组装并通过校验后才执行。若没有任何可见片段，在提供商支持时仅调整草稿恢复轮的推理强度。 |
| 用户要求改进旧作品 | 模型可查找并读取原件，定位需要更新的源码片段。局部修订按文件 ID、SHA-256 和原文生成新文件。重复文本可以指定已核对的 UTF-8 字节偏移。原件保留。 |
| 流中断、任务暂停或服务重启 | 传输故障按重试策略处理。恢复时重查会话授权、已完成回执和草稿游标；已确认的交付沿用回执。持续无进展、权限变化或压缩后仍装不下必要输入时，向用户说明原因并保留可恢复状态。 |

注册分身从 `conversation/agent_loop.py` 进入 ReAct 循环。`loop/builtin_tools.py` 和 `registry.py` 按入口绑定本轮授权工具，主模型可直接流式作答，也可发起原生工具调用。OpenAI、Anthropic 和 Gemini 适配器保留调用 ID，将每个工具结果配回原调用。独立工具可同批请求，执行器逐项返回回执。参数错误、查无原件和重复调用将原因交给模型处理。独立任务用 `send_message`、`end_task` 或 `wait_for_user` 提交本轮动作。结束前由本地规则校验交付、附件引用和权限。

`loop/context.py` 按完整的工具调用及其回执组裁剪上下文，较大的回执由 `read_step_receipt` 分页取回。`read_session_file` 可查找会话目录和读取当前授权原件。`create_html` 用于网页和动画，`edit_html` 用已读原件的文件 ID、SHA-256 和文本片段局部修订。`loop/drafts.py` 在长 HTML 截断后保存有效前缀，模型通过 `append_html_draft` 按 UTF-8 字节游标续写。原件交付按入口经 `find_material`、`send_material` 或对应的公开资料工具处理，准备回执和最终交付均核验文件版本。`search_materials`、`read_material` 和 `run_python` 直接检索、读取或运行沙箱。需要多步操作时，由同一个主模型循环接续。

`loop/runtime.py` 用 v2 检查点记录轨迹、产物及暂停状态。`loop/store.py` 用写入者和修订号核验原子提交。历史暂停态恢复时保留已校验的产物、来源和只读摘要，从空的 v2 轨迹开始。未确认的外部副作用需要先核对。模型正常结束却仅返回思考内容时，符合恢复条件可重试一次，两次用量合计。

Web、分身普通消息、独立任务及小镇调用共享资料和模型边界，但历史按账户、平台、调用者、目标和会话隔离。显式引用的有效原件在下一轮按模型可用预算进入上下文，保留来源、覆盖范围和续读位置。其他会话原件由模型按需查找、读取。过期、已删除及超出当前权限范围的条目从工具结果和自动注入中排除。检索到的公开材料不自动转成引用或对外附件。

公开分身目录由获准查询的入口绑定 `list_avatars`。小镇临时会话配置 Embedding 后可混合检索公开资料、读取和交付公开原件、运行离线 Python，以及生成 HTML 网页或动画。它使用可复用的独占临时工作目录。确认完成、取消或等待确认超时后，撤销临时地址并回收生成文件。个人聊天及协作任务可通过 `ask_user` 暂停。用户按问题 ID 作答后继续原轨迹，恢复时重新校验账户、来源和工具授权。只配置 LLM 的入口按已填写资料直接作答。

个人 AIP 请求先持久认领命令，短回答直接返回；超过约 1 秒则返回 `working` 并后台执行。`get` 查询最新状态，`continue` 追加等待态任务，命令账本保证重发和重启后不重复收费。客户端断连不停止后台任务；明确取消会停止，服务关闭会排空，重启恢复未完成任务为失败而不自动重放。

独立任务通过 revision 和终态校验阻止迟到提交与续接。成功完成时写入统一的七天工作区截止时间，双方分别收到转存提醒。未完成任务的工作区原件与预览不单独计时。清理会保留聊天及按参与方授权记录的过期文件标记；主会话和各任务分别保留一份共享原件，参与者使用本人设置和资料权限。手动删除撤销本人引用，最后一位参与者删除后回收原件。删除未完成任务不回写总结。记录全部删除在服务端跨页执行，仅影响授权范围；活跃工作和必要审计保留。分身历史删除推进本人的展示与摘要游标，共享文件按参与者引用清理。清理失败单独记录，收发队列继续处理。

Soul 的生效指针只有一个，且与所有者关联校验。手工素材和记忆修订须确认/审核；自动学习只提交封闭风格证据给 EverOS，增量游标只在成功后推进，事实无公共检索入口。个人 Web 任务绑定启动时的已批准风格。自动学习发布同账户后继版本时，已绑定的任务和检查点可继续；停用、人工切换及原版本变动仍须重验。

## 用户存储布局

用户私有文件统一位于 `data/users/<稳定内部用户ID>/`，包含 `attachments`、`chat_attachments`、`knowledge`、`everos`、`skills`、`identity`（ACS/证书）。不使用会过期的 Access Token 作目录名。启动时先迁移旧目录，冲突立即停止，不覆盖文件；无法确认归属的旧文件保留在 `maintenance/unowned-storage`。会话原件与预览在 `chat_attachments/<会话ID>/`，由数据库校验用户、会话和文件的归属。既有原件及预览按登记记录迁移，删除会话后回收对应目录。已转存副本独立保留。

数据库中的会话、聊天、Soul 版本及资料关系仍以 user_id 隔离，保留共享数据库以支持事务、跨分身任务和审计；主密钥、系统身份、平台配置也保持共享。升级须先停止服务并备份。

Web 聊天由 `conversation/jobs/store.py` 管理请求唯一性和事务，`conversation/jobs/runner.py` 管理应用生命周期内的执行，`conversation/jobs/pipeline.py` 携带服务端授权上下文，`core/execution.py` 在模型和沙箱边界触发撤权复核；最终提交同事务再核验。HTTP/SSE 仅提交和订阅，不能通过浏览器连接控制生成。`reply` 与 `stream` 使用同一生成路径。自动标题在释放回答租约后执行，不阻塞下一轮。持久任务状态独立于最后一轮会话快照，故 A/B/A 重放仍能定位 A 的原结果。

ACPS 协议账本保留实体、对端、命令和会话的身份边界，不与 Web 请求 ID 混用。对端先确认接收 working；后续 get 仅查询状态，不重新执行。后台进程消失或结果无法确认时释放占用，不承诺外部 API 的 exactly-once，也不盲目重发模型调用。
