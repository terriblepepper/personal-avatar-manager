# 知识库、Soul 与持续学习

## 资料与人格分工

资料文件保存事实原件，按权限检索；Soul 内知识库保存人格和表达风格的塑造素材。两者共用文件管理器，但不因为文件公开就自动进入 Soul，也不因为进入 Soul 就对外公开原件。

每个账户仅有一份当前生效 Soul，`active_souls` 指向经所有者约束校验的构建。旧构建记录不是第二份当前人格。本人和外部聊天可使用已生效表达风格，但外部问答不能因此获取私密资料。

## 构建与修订

知识库支持目录、本地上传、资料库多选导入、说明、预览、重命名和批量删除。新构建默认使用 PNG、JPEG、WebP、GIF、BMP 图片及 MD、TXT、DOC、DOCX 文档。已有其他格式的素材可继续管理，默认跳过；已构建后新增素材合并进入增量完善草案，避免每次重复分析旧材料。

构建使用素材分析、题库问答和用户补充，生成个人形象概览及 voice、interaction、wording、appearance、boundaries、examples 六项表达特征。完成后清理未回答的补充问题，实际回答与补充仍作为记忆证据。失败可保留已完成问答和成功缓存重试。

用户在概览处继续完善、重新创建、停用或展开记忆树。手动编辑素材、风格或记忆节点创建新修订，经过确认和平台审核后切换生效指针；拒绝和失败不覆盖当前 Soul。删除旧构建记录保留素材与当前 Soul，全量记录删除跳过未完成构建、当前生效版本和内部自动学习版本。

## 持续学习

Soul 审核通过并生效后，才可在本人会话开启自动学习或立即学习。停用 Soul 会关闭各会话的自动学习。Soul 重新生效后，可按会话开启。

自动学习只处理本人真实用户气泡，不采集助手、访客、其他账户或任务事件气泡。先提取并验证封闭表达标签，再交给 EverOS；不把聊天全文、联系方式、身份事实或临时情绪直接当作长期人格。

EverOS 原生 Episode/Profile 分层维护情境表达和长期偏好。每轮继承当前生效记忆，只处理新增证据，成功才推进游标。持续学习直接更新当前风格和六项概览，只在 Soul 旁显示状态，不进入人工修订列表或消息通知。清空会话不会抹去已经成功学习的风格。

## EverOS 与隔离

固定 EverOS 1.5.1，源码和许可证位于 `vendor/EverOS`。桥接进程 `tools/everos/worker.py` 使用当前服务 `sys.executable`，与平台共用 `.venv`，不另建环境、不启动独立 EverOS HTTP 服务。

父进程持有模型 Key 和 PostgreSQL 连接，通过受控协议为 worker 执行模型和存储操作。每个账户的 `data/users/<uid>/everos/` 保存 Markdown、画像及项目提交日志；队列、记忆向量和暂存数据写入 PostgreSQL。检索限定已授权所有者、索引签名及项目，未改动证据和向量可在其权限范围内复用。

## 额度、并发与媒体

Soul 直接上传总额度 10 GiB；从资料库导入不占此额度，但原件仍需通过权限与格式校验。资料文件索引和 Soul 素材分析共用每账户最多 10 个工作槽，不是各自再开 10 路。最终记忆提交保持一致性。

未配置嵌入时停止 Soul 构建/加载，不影响一般聊天。构建时由 LibreOffice 将 DOC/DOCX 转成 PDF，提取正文并按需用视觉模型分析图片与图表。预览使用 PDF，下载保留原件。其他资料可保存在独立资料库。Soul 嵌入仅在明确请求尚未发出且错误可恢复时额外重试，间隔 2、5、10 秒。服务端是否已处理无法确认时保留失败状态，由操作者核对后决定是否重试。

## 代码与验证

`avatar/knowledge/service.py` 管理构建、素材和生效；`style_learning.py` / `style_traits.py` 管理增量与安全风格证据；`everos_memory.py` 管理进程桥和缓存，`everos_storage.py` 管理 PostgreSQL 队列与向量；`question_bank.py` 管理有界、幂等题库导入。

```bash
.venv/bin/python scripts/run_tests.py --jobs 4 unit -q
```

在同一停写窗口导出 PostgreSQL，并归档保险库主密钥、知识库原件、EverOS 记忆文件、身份材料及私有配置。详见[备份与恢复](PostgreSQL运行.md)。
