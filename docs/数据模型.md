# 数据模型

后端必须通过 `DATABASE_URL` 连接 PostgreSQL。账户、会话、索引状态、资料向量、EverOS 队列与向量及系统 AIP 账本均存于业务主库。
基础结构在 `avatar/core/postgres_schema.py`，其初始化逻辑调用系统 AIP、资料索引和 EverOS 存储模块安装相关表。
数据库结构与历史数据迁移分别校验，业务迁移标记保存在 `data_migrations`。

下表按职责列出逻辑表。分身协作的 `agent_dialogues.agent_checkpoint` 记录待继续的执行信息，个人协议在 `avatar_aip_tasks` 的任务文档中保存检查点；每个入口维持原有身份和任务作用域。PostgreSQL 部署使用 psql 的 `\dt` 核对实际表结构。

| `platform_bindings` | 与外部平台（如小镇）的账号绑定 |
| `platform_entry_tokens` | 平台落地入口的一次性令牌 |
| `profile_records` | 用户资料草稿与当前值 |
| `profile_submissions` | 资料提交快照（含审核时的 `snapshot`，用于比对是否变更） |
| `account_reviews` | 账号审核记录 |
| `audit_events` | 审计事件流（通知中心由此投影「最近动态」） |
| `login_devices` | 登录设备记录 |
| `login_limits` | 登录尝试限流 |
| `recovery_limits` | 找回密码限流 |
| `provision_jobs` | 账号开通作业队列 |
| `identity_migration_previews` | 身份迁移预览结果（提交前留痕） |
| `avatar_records` | 分身记录（资料、ACS 引用） |
| `avatar_identity_changes` | 分身身份变更历史 |
| `avatar_identity_jobs` | 分身身份维护作业（管理端可刷新、重试） |
| `avatar_entity_ports` | 分身到 AIP 端口的持久分配（`10001`–`15000` 独占） |

Keycloak 的 `issuer + sub` 与内部账号唯一绑定；**不按手机号或学号自动合并**，避免误关联。

## 会话与聊天生成（14）

| 表 | 作用 |
| --- | --- |
| `chat_conversations` | 会话列表、归属、渠道、摘要与压缩计数 |
| `chat_messages` | 历史消息（用户/助手成对写入，含 `used_skills`、`tool_events`、`responder_aic`） |
| `chat_pending` | 会话中待处理的输入 |
| `chat_generation_jobs` | **生成任务账本**：`request_id`、请求指纹、状态机、快照与时间戳 |
| `chat_agent_pauses` | 每个父会话至多一条暂停记录，关联原任务、暂停标识、检查点及待关联的输出文件 ID，删除会话时级联清理 |
| `agent_loop_runs` | 私有运行记录，按所有者、入口、会话或协议任务、运行 ID 隔离。记录当前写入者、修订、待办、已核验回执及草稿游标 |
| `agent_loop_chunks` | 按运行、草稿和 UTF-8 字节偏移保存文本分片，也可保存沙箱二进制回执。删除运行时级联删除 |
| `chat_session_skills` | 会话内显式引入的技能 |
| `chat_files` | 会话临时文件（引用、生成物、peer 共享） |
| `chat_file_usages` | 消息实际使用了哪些会话文件 |
| `chat_message_materials` | 本人消息交付的资料原件引用，position 保留模型选择的顺序，随消息或资料删除而撤销 |
| `conversation_diagrams` | 会话产生的 Mermaid 图形与缓存 |
| `agent_pending_inputs` | 协作中用户补充的消息/文件/技能（放行后消费） |
| `record_dismissals` | 通用记录列表中被用户关闭的条目 |

生成任务状态：`queued` / `running` / `succeeded` / `failed` / `cancelled` / `indeterminate` / `awaiting_input`。
只有 `queued` 和 `running` 占用生成槽位。`awaiting_input` 结束本次生成，用户可以在原会话新提交一次补充或结束操作。同一账户下 `request_id` 唯一：
同 ID 同指纹幂等返回原任务，同 ID 不同指纹返回 409；同一会话已有活跃任务时返回 409「上一条消息仍在生成」。

新动画作为 HTML 会话文件交付。历史动画源码随消息保存在 `chat_messages` 或分身发言记录中。仅在用户确认转存后，系统才把规范化的 `.avanim` 原件写入资料库的 `attachments`，按所有者和内容 SHA-256 去重。会话副本沿用 `chat_files`、`chat_file_usages` 及同实例分发记录 `agent_task_files`。持续引用通过 `chat_files.source_animation_id` 关联资料，删除资料时级联撤销。一次性发送的会话副本独立保留。资料及会话文件的 `animation_metadata` 存放标题、标签和时长，`animation_digest` 存放规范化内容摘要。

## 资料与检索（12）

| 表 | 作用 |
| --- | --- |
| `attachments` | 资料主表：归属、相对路径、大小、SHA256、可见性、解析状态与版本 |
| `attachment_collections` | 上传批次 |
| `material_folders` | 多级目录与目录说明（拖拽上传保留层级） |
| `file_rag_documents` | 索引队列与状态；新增 `active_publication` 生效发布指针、`legacy_backfill` 词法回填标记，工作租约与下次调度时间 |
| `file_rag_nodes` | 父子分块结果与文本 |
| `file_rag_epochs` | 索引轮次版本，用于整体重建与新旧切换 |
| `file_rag_gc` | 待回收项（新记录延迟 1 小时、被替换旧记录延迟 7 天），保证重建不出现检索空窗 |
| `embedding_settings` | 每账户嵌入模型配置（独立于聊天模型） |
| `rag_schedule_users` | 最近服务时间，供全局有界索引调度按账户公平轮转 |
| `rag_publications` | 不可变发布清单：账户、文件修订、模型签名、向量集合、分块 ID、覆盖信息、`manifest`、词法就绪标记 |
| `rag_lexical_records` | 按账户、集合、记录 ID 唯一的派生词法正文与元数据 |
| `rag_vector_records` | 按账户、集合、记录 ID 唯一，保存正文、JSONB 元数据和 `REAL[]` 向量 |

在线检索仅拉取当前发布清单和调用方同时授权的记录，在应用内计算精确余弦与 BM25Plus，再做 RRF。PostgreSQL 的词法查询基于 `rag_lexical_records.tokens`。

历史索引迁移保留 `file_rag_nodes`、向量和正文，缺少发布清单时按既有节点补建 `legacy=1` 的清单并标记词法回填。后台使用导入的正文生成词法记录。缺失向量或正文需要核查，不会自动触发付费嵌入。见[迁移说明](PostgreSQL运行.md)。

新发布先校验向量数量、维度、有限值及向量与词法记录完整性，再在一个主库事务中切换节点和生效指针。发布与 GC 使用同一账户锁，避免 GC 删除正在验证的暂存记录。同内容重建失败不会覆盖旧发布清单；`active_index()` 仅在文件修订与模型签名匹配时返回旧清单。现有聊天检索仍保留自己的状态校验；本次尚未将该恢复入口和独立 FTS 搜索接入完整混合检索流程。

`manifest.expected_chunks/processed_chunks` 和 `chunks_verified` 仅表示本次发布的分块一致性；没有权威页数或图片清单时，对应字段与 `complete` 保持 `null`，不得把未知完整性写成已完整解析。旧清单同样保留未知覆盖信息。向量存为 PostgreSQL 数组，无需安装 pgvector 扩展。

## 数据目录

```text
data/
├── pgsql/                  自管 PostgreSQL 的物理数据目录（外部数据库部署无此项）
├── initial-admin.txt       首次启动生成的根管理员密码
├── model-secrets.key       模型密钥加密主密钥（丢失则无法解密已存 Key）
├── users/<uid>/            按账户隔离的 attachments、chat_attachments、knowledge、everos、skills、identity
├── system_identity/        系统与本体身份、证书及私钥
├── test/                   测试原件与工作区，测试状态位于专用 PostgreSQL schema
└── maintenance/            维护记录、迁移冲突或待核对文件
```

独立任务的工作区有效期使用 `agent_dialogues.expires_at`，从成功完成起计七天。到期后 `agent_task_members.expired_files` 仅保留本方曾收到的生成文件展示元数据；原件、预览和下载授权随工作区回收。私有存储按内部用户 ID 隔离并拒绝符号链接。会话上传原件、生成文件及预览位于 `users/<uid>/chat_attachments/<会话ID>/`，数据库仅使用会话 ID 和文件 ID 定位。EverOS 使用账户哈希区分项目内的记忆所有者。

## 备份与回退

- 结构化状态与文件必须**一起**备份：只备数据库或只备 `users/` 都会出现引用缺失。
- 停止应用写入并保持 PostgreSQL 在线，导出逻辑备份，同时归档 `.env`、数据目录中的原件、密钥和身份材料。备份存放在项目外。
- 恢复时使用同批数据库、配置、密钥、用户文件和匹配的应用版本。
- 数据库保存 EverOS 队列和向量，文件归档应包含 `data/users/<uid>/everos/` 的 Markdown、画像和恢复日志。详细边界见[PostgreSQL 运行](PostgreSQL运行.md)。
