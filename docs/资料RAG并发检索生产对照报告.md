# 资料 RAG 并发检索生产对照报告

2026-11-19 · v1.1.0

在同一台生产服务器上，8 个工作线程连续执行资料检索，优化后的 PostgreSQL 达到 **27.18 次/秒**，是旧 SQLite/Chroma 方案（6.26 次/秒）的 **4.34 倍**。P95 从 **1,424.3 ms 降至 1,276.4 ms**，降低 **10.4%**。这是已取得查询向量、重复访问相同授权范围时的检索层耗时。更换范围时，旧方案的中位数仍较低。

## 持续 8 并发

每种实现在每轮计时前预热 12 个查询，共执行两轮，每轮计时 240 次。第一轮按旧方案、原 PostgreSQL、优化后 PostgreSQL 执行，第二轮反序。三种实现各完成 480 次，合计 1,440 次。吞吐按总请求数除以两轮总耗时计算。所有分位数合并单请求样本计算，单位为毫秒。

| 旧 SQLite/Chroma | 6.26 | 1,365.6 | 1,424.3 | 1,439.0 |

## 对照与一致性

- **数据。** 三个活动集合分别有 988、93、84 条共享记录。逐条比对两端的正文、元数据和 4,096 维 float32 向量。各留出 4 条作为查询，从候选中排除全部留出记录，剩余 984、89、80 条。三组等频出现，查询按留出正文的前 72 个字符和原向量构造。
- **实现。** 旧代码取自 `647210f`，调用 `ChromaFiles.search`，使用冻结备份的独立副本，包含 SQLite 元数据、Chroma HNSW 和 BM25/RRF。原 PostgreSQL 基线为 `28e5a73`。两个 PostgreSQL 版本均调用生产检索入口 `PostgresFiles.search`，使用同一生产库的只读连接。三组均返回最多 12 条。
- **结果。** 12 个主查询中，两版 PostgreSQL 返回的正文和顺序全部一致。36 次变更候选范围后，返回记录、正文及顺序也全部一致。与旧方案相比，12/12 个主查询的首条相同，11/12 的完整排序相同，Top-12 共重合 143/144 条。这是结果一致性，用户相关性仍需人工标注才能评估。
- **环境与边界。** 单机 Linux x86_64、Xeon Gold 5218R、Python 3.13.15、NumPy 2.5.4、ChromaDB 1.5.9。测试进程将 BLAS/OpenMP 工作线程设为 1，Chroma Rayon 线程设为 2。生产库单句超时 8 秒。使用预先取得的查询向量，计时从检索调用开始至返回，排除授权目录构造、外部模型、HTTP 和聊天生成。结果以本机、这些语料和查询为限。报告仅保留聚合数值。

## 实施的优化

原实现每次从 PostgreSQL 读取允许范围的向量，解码正文、元数据、词项并重新构造 BM25。大集合单次可涉及 984 条 4,096 维向量。单独复用向量的试验在 8 并发出现退化。正式实现同时复用两个可重复计算的部分。

1. 每次查询在只读、可重复读事务中，按账户、集合和本次允许的记录 ID 计算向量行与词法行的版本签名。签名与元数据过滤条件共同限定可复用的 BM25 语料。仅重复出现的范围进入语料缓存。
2. 最多每 256 条记录组成一个向量块，按记录 ID 和版本复用矩阵与范数。矩阵保留 float32，点积和范数用 float64 计算。每个查询仍独立计算余弦、BM25 和 RRF，保留现有排序与去重规则。
3. 每个检索存储实例共享 96 MiB 缓存计量预算，条目命中有效期 300 秒。变更范围试验结束时计量为 93.31 MiB。进程峰值还包含并发计算的临时数组和解释器开销。PostgreSQL 负责持久化和版本判定，本次未新增 Redis 键或数据库迁移。

32 项定向 RAG 测试通过，覆盖同名记录的账户隔离、权限子集，以及独立事务更新向量、更新词项和删除后的下一次查询。

基线提交 `e6fcc32`。所有写入发生在专用 PostgreSQL 测试数据库的临时 schema。HTTP 测试使用独立 Redis 和固定模型替身。健康、登录态、审计分页、会话改名、通知角标、资料上传、下载、预览、转存、协作、清理、个人流式回答和首次索引各测 1、4、8、16、32 并发，基线共 1,728 个工作单元，错误数为零。每个 SSE 请求校验最终回答。基线 8 并发聊天 P95 为 14.29 秒，同时测得事件循环延迟 P99 为 867 毫秒，锁 SQL P99 为 2.11 毫秒。

### 阶段 A · 模型连接与 PostgreSQL 包装层

在同机 TLS 模型替身上，固定首包延迟 2 ms。连续 12 个五步回合原先需要 60 次 DNS 验证和 TLS 连接。连接复用后，在同一验证有效期内串行请求共用连接。模型和 OIDC 使用各自的传输池，每个请求独立持有凭据与 Cookie。五步串行回合 P95 从 50.49 降至 34.23 ms，4 并发从 115.65 降至 39.14 ms。此处计时包含替身网络和读流，不含真实模型推理。

隔离 PostgreSQL 16.15、psycopg 3.3.9。同一兼容入口执行 128 条 UPDATE 的一批写入，P50/P95/P99 从 41.450/54.686/64.342 降至 8.350/26.470/33.070 ms，吞吐从 23.58 增至 95.60 批/秒。libpq 协议跟踪中，8 条冲突可忽略的插入从 9 个 Sync 降为 2 个，调用方仍得到最后一条的行数。热主键查询 P95 从 0.393 降至 0.275 ms。SQLite 兼容语义、最后生成的主键及批次失败回滚均经核验。源代码字面 SQL 使用每份元数据最多 512 项的翻译缓存。

对 1,000 行、12 列做行转换与字典化，两轮反序对照的 P50 从 3.670/3.704 降至 2.536/2.572 ms，分配峰值从 393,112 降至 361,112 字节。含数据库传输的同类读取 P95 为 7.611/7.725 ms，端到端未见改善。psycopg 原有 prepare 阈值为 5，每连接缓存上限 100，本轮沿用。

### 阶段 B · 事件循环与进度投递

路由静态分析得到基线 203 条，45 条为 async、158 条为 def。个人生成任务提交改用同步路由后为 44/159。核对范围包括路由直接调用、SSE 订阅迭代、模型能力探测、OIDC、转存及后台任务。在隔离 Uvicorn 的注销、上传、模型设置、嵌入设置、动画等九条路由，向同一数据库调用注入 90 ms 查询延迟并返回同一 409，九次调用均移出主循环。5 ms 心跳的最大漂移从 116.89–123.45 ms 降至 0.78–1.51 ms。该试验衡量一次慢数据库调用对同进程其他请求的影响。

一次正常 SSE 回答在主事件循环执行了 99 笔同步数据库事务。35 次生成快照写入占这些事务耗时的 68%。生成任务现在按原顺序等待快照、租约、权限复核及最终状态写入，写操作在线程内完成。收尾按本次取得的租约释放会话。每次请求的路由总时长含流式响应结束，管理员可读取最近 256 个样本的分位数，以及数据库连接获取、写锁等待、解析、可视文档子进程启动和事件循环延迟。指标键来自路由模板和固定阶段。

前端 Chromium 在状态响应挂起 11 秒时测得同一协作任务卡的重叠请求由 3 次变为 1 次，恢复前台后补查一次。个人生成轮询的 10.5 秒后台观察从 11 次变为 0 次，连续 503 的 10 秒内从 10 次降至 3 次；恢复后取到最终状态。隔离 Nginx 1.24 对哈希 JS 的压缩将 2,145,899 字节降至 544,561 字节。已验证 ETag 304、私有响应不缓存、2 MiB 上传和 SSE 分块交付。项目运维文档给出可选配置。

另一次 SQL 指纹采样定位到沙箱资料清单。构造输入映射时，即使不执行沙箱，也会为每份候选资料单独查路径。在 232 份资料上，连续五轮的每轮业务 SQL 从 233 降至 1，中位耗时从 69.53 降至 4.66 ms。实际打开原件时按本次授权和账户目录定位，已验资料撤权、文件删除和同轮多份文件独立读取。

### 阶段 C · 资源隔离、检索与发布验收

此次变更分三个 PR。阶段 A 修改模型连接、OIDC 与数据库兼容入口；阶段 B 修改路由、会话任务、进度快照与 Vue 轮询；阶段 C 修改账户写锁、缓存批读、注册、解析进程及精确检索。用户与模型的 API 凭据沿用原配置。隔离库未启用 pg_stat_statements，SQL 统计使用客户端计数、pg_stat_activity、pg_locks 和 EXPLAIN (ANALYZE, BUFFERS)。性能数据仅含聚合计数与 SQL 指纹。

### 解析进程与 Web worker

Linux 上仅将不大于 4 KiB 的纯文本原件送入最多两个按需启动的子进程；更大文件由原隔离 CLI 通过同一已打开的只读 FD 读取，不设业务文件大小上限。后台索引最多借用一个，前台读取可使用空闲进程。父进程完成鉴权后打开普通文件，Unix socket 只传只读 FD 和有限 JSON 参数。子进程不接收路径、Python 代码或模型凭据，每次任务关闭 FD、清理搜索词缓存。复用路径的单任务共用 45 秒排队与执行预算、30 秒 CPU，每进程 512 MiB 地址空间和 64 个 FD，继承更低的宿主限制。64 个任务或 5 分钟回收，应用关闭时回收。执行中崩溃将当前任务报错，下一独立请求拉起新进程。PDF、Office、OCR、计费 EverOS 仍按原进程边界执行。Deno/Pyodide 继续逐任务隔离。

- 曾验证 PostgreSQL `NOTIFY`，在 8 写入者的信号微基准中使 P95 从 14.52 升到 18.88 ms。正式方案改用事务内事件表，聊天中间快照提交后唤醒本进程 SSE，避免高频进度逐条增加事件表写入。
- 核对事务回滚、收件人隔离、SSE 变更提示、Redis/Kafka 停服务和降级。账户鉴权复用一次池连接，原写锁、任务租约和小镇客户端契约沿用。正式生产峰值需另行持续观察。
