# 小镇接入交接

契约整理日期：2026-11-09。本文描述当前代码，不固定宣称某个 AIC 在线；以实时 ACS 和平台在线状态为准。

## 地址与职责

Web 用户入口 `/`，管理入口 `/admin`，默认 Web 端口 18080。管理 ACPS RPC 使用 `AVATAR_SYSTEM_AIP_PUBLIC_URL`，个人 RPC 使用 10001～15000 的独占端口；以 Registry 正式 ACS 中 `endPoints` 为准，不把浏览器域名或 Web App URL 当作个人分身 RPC。

管理系统查询类技能返回结果文本/结构化数据，例如公开分身列表；需要进入网页的服务返回 URL。个人分身不需要 Web App URL。管理和个人实体有不同 AIC、ACS 和证书。

## 认证与请求者

Web 使用同一 Keycloak 的授权码/PKCE：issuer 为 部署环境中的 `AVATAR_OIDC_ISSUER`，Client ID 由 `AVATAR_OIDC_CLIENT_ID` 指定，公开客户端不配置 Secret。同一 Realm 的浏览器登录态可实现 SSO，但浏览器 Cookie 不是跨平台 RPC 的访问令牌。

mTLS 证明调用智能体 AIC。小镇未携带用户 Token 时，个人和管理协议服务按访客规则工作，不据此创建/绑定业务账号。若显式提供 Token，则核验签名、issuer、audience、azp 及主体；无效 Token 不能降级为匿名。Web 后台仍要求登录。

平台内部分身通信额外携带发起方所有者的 Keycloak ID，并核对其与 mTLS 对端的已绑定身份：

```json
{
  "type": "task-command",
  "id": "command-001",
  "sentAt": "2026-11-09T08:00:00Z",
  "senderRole": "leader",
  "senderId": "发起方AIC",
  "mentions": ["目标AIC"],
  "taskId": "task-001",
  "sessionId": "session-001",
  "command": "start",
  "commandParams": {
    "requester": {
      "id": "发起方所有者的Keycloak-sub",
      "issuer": "https://id.example.org/realms/example"
    }
  },
  "dataItems": [{"type": "data", "data": {"peerDialogueTask": "task-001"}}]
}
```

这是平台配对任务的命令正文，`peerDialogueTask` 引用已经授权的内部任务，不供小镇伪造。小镇普通问答的 `dataItems` 使用 `[{"type":"text","text":"你好"}]`，或者已审核技能的固定 `skillId/query` 数据格式。外层 RPC 使用标准 ACPs SDK 封装。

## 个人问答与状态查询

| 命令 | 行为 |
| --- | --- |
| `start` | 新 taskId 发起问题，持久认领命令 |
| `continue` | 同一 taskId/sessionId，新的命令 id，在等待输入/确认态追加问题 |
| `get` | 查询原任务，不重复调用模型 |
| `complete` | 确认结果并结束任务 |
| `cancel` | 明确停止任务，取消后台生成 |

耗时超过约 1 秒时，分身先返回 `working`。小镇通过原 `taskId` 和 `sessionId` 轮询 `get`。阶段变化或进入新的 8 秒心跳周期后，下一次查询返回新结果消息（`id`、`sentAt` 更新）。阶段说明和等待时长在 `status.dataItems`，`stateChangedAt` 保留进入 `working` 的时间。

如果小镇设置 45 秒无响应降级，应收到新进度消息后重置无响应计时，并继续查询原任务。小镇可独立设置总时限。分身单轮等待期限为 8 分钟。模型上游响应流连通后暂停 AIP 倒计时。响应结束或断流后重新计算完整的 8 分钟，重连成功后再次暂停。模型流自身的空闲检测仍然生效，只发送心跳不会延长模型流的空闲时限。进程自动恢复沿用已保存期限。非流式等待超时会返回 `failed` 和原因。显式 `continue` 开始新一轮，客户端断开不会取消后台任务。

小镇临时问答不支持模型中途提问。资料不足时，分身在最终答复中说明缺口。执行故障需要恢复时仍可能返回 `awaiting-input`，此时停止轮询并展示 `status.dataItems` 中的提示。继续时沿用原任务和会话标识，用新命令 ID 发送 `continue` 和补充文本。结束时发送 `cancel`。公开 HTTP 访客须沿用原 Cookie，在 `message` 字段填写补充文本。

收到 `awaiting-completion` 后，读取 `products[].dataItems` 中的文字和标准 AIP 文件项。正文不列 RAG 或源文件引用，明确交付的原件和生成文件继续通过文件项提供。生成的 HTML 网页和动画会以 Markdown 的 HTML 代码块插入小镇答复正文，供小镇识别渲染。文件项同时提供下载，包含名称、MIME 类型、大小、SHA-256 和临时地址。客户端在发送 `complete` 前接收正文及所需文件，等待确认最多 5 分钟。确认完成、取消或等待确认超时后，临时地址失效，生成文件立即回收。不要在日志或聊天正文中记录地址。同一任务在确认前继续时，可按需读取已有生成文件。HTML 预览须隔离脚本并禁网。连接超时或发送结果待核实时，先查询原任务。

重复命令 ID 幂等，包括重新连接和服务重启。不同新续问不能并行插入同一正在处理的任务。已 completed/canceled/failed 的任务不复活；需要新 taskId，可沿用 sessionId 保留前文。首个请求没有 sessionId 时，后续沿用返回值。等待确认超过 5 分钟会在后续访问时结算失败。

仅配置对话模型的分身直接根据已审核的公开表单资料作答，无 Agent Loop、文件检索或工具。历史按目标分身、mTLS peer、访客、group 和 session 隔离。配置了 Embedding 时，分身可按需混合检索和读取公开资料、交付已保存的公开原件、通过离线 Python 和 HTML 生成作品、查看和修订本轮工作区文件。工作目录清空后复用。任务文本和已确认的执行进度按原会话范围保存。工具只能访问公开资料和本次的生成件，无法访问资料所有人的私密工具或工作区。

## 公开访问额度

分身所有者可在「账户设置 → 小镇访问额度」设置每访客和总日次数，两项默认不限。达到任一额度时，`start` 或有新内容的 `continue` 返回 `-32010 今日公开对话额度已用完`。失败的命令没有创建新任务。按 UTC 日期计数，重复命令、自动恢复和控制命令不重复计费。

## 上线与排查

平台与 Registry 审核、证书签发、CA 状态和端口监听分别检查。CA 429 时显示等待恢复并遵守冷却，不绕过证书验证；Registry 通过不能直接标成可通信。

个人和管理私有身份目录的 `rpc-diagnostics.jsonl` 记录有界脱敏请求/响应：请求头只记名称，敏感凭据遮盖，正文只记长度和 SHA256。定位问题时核对命令、taskId/sessionId、时间、结果 ID、状态及取消来源。个人 AIP 的模型尝试和任务结算在服务日志中通过 taskId、sessionId 和 run_id 关联。取消命令另记命令 ID，轮询记录使用 DEBUG 级别。任务轨迹仅保留状态、阶段和重试信息。不要在交接文档或聊天粘贴 Token、私钥和密码。

真实小镇端到端操作需要双方服务可用；开发验收仅使用隔离 mTLS 和模拟模型，见[验收说明](验收说明.md)。
