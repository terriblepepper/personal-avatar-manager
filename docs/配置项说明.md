# 配置项说明

启动配置来自环境变量，读取入口是 `avatar/core/config.py` 的 `Settings.from_env()`。
`run.sh` 和 `service.sh start` 会在启动前自动 `source .env`；直接运行 `avatar-platform` 或脚本时需自行导出。
样例见 [`.env.example`](../.env.example)。
模板列出常用部署项，下表也列出可按需覆盖的默认值；同步到已有 `.env` 时保留实际身份、凭据、网络地址和功能开关，不直接覆盖部署值。可选的 `AVATAR_DATA_DIR` 保持注释，未设置时使用下述默认目录。

> 注意：`Settings` 是不可变对象（frozen dataclass），进程启动后改环境变量不会生效，需要重启服务。

## 数据目录的选择

- 源码运行：默认 `./data`。
- 安装包运行：默认 `$XDG_DATA_HOME/personal-avatar-manager`（未设置 `XDG_DATA_HOME` 时为 `~/.local/share/personal-avatar-manager`）。
- 显式指定：`AVATAR_DATA_DIR`，会做 `expanduser().resolve()`。
- 启动脚本以 `umask 077` 运行，新建的数据文件默认仅属主可读写。

## 基础与网络

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `AVATAR_PROVIDER` | `demo` | 身份注册适配器：`demo` 为演示注册，`acps-direct` 为正式直接实体注册；登录认证由 OIDC 配置控制 |
| `AVATAR_HOST` | `0.0.0.0` | uvicorn 监听地址（由 `run.sh` / CLI 使用） |
| `AVATAR_PORT` | `18080` | uvicorn 监听端口 |
| `AVATAR_VERSION` | 安装包版本 | 登录页、平台 API 信息和管理 ACS 的版本；空值回退安装包元数据，未安装源码回退 `pyproject.toml`。个人分身 ACS 保留用户填写的版本 |
| `AVATAR_DATA_DIR` | 见上 | 私有数据根目录 |
| `DATABASE_URL` | 必填 | 后端 psycopg 的 PostgreSQL DSN，例如 `postgresql:///avatar?user=avatar_app`。启动前须配置，详见[PostgreSQL 运行](PostgreSQL运行.md) |
| `AVATAR_REDIS_SOCKET` | 空 | 可选读缓存。源码模板使用项目根下的 `redis/redis.sock`，留空关闭。Redis 失联时从业务库读取。相对路径以进程工作目录为准。 |
| `AVATAR_PG_HOME` | `~/.local/pgsql-16` | `service.sh` 启停数据库用的 PostgreSQL 二进制根目录（shell 读取，不经 `Settings.from_env`）；数据目录固定为 `data/pgsql`，任一不存在时跳过，见[PostgreSQL 运行](PostgreSQL运行.md) |
| `AVATAR_PUBLIC_URL` | 环回地址，端口取 `AVATAR_PORT` | 对外访问地址，用于回调与生成链接；读取时会去掉结尾 `/` |
| `AVATAR_SANDBOX_HTTPS_RESOURCES` | `{}` | Python 工具可读取的固定 HTTPS 资源，以 JSON 对象映射名称和完整 URL。仅配置允许所有已授权个人 Web 会话读取的公开数据，不填写凭据或内网管理地址。每步最多选两项，每项 1 MiB，共用 10 秒时限；仅 GET，不跟随重定向，不接受查询参数、通配符和自定义端口。脚本通过 `/workspace/https/名称` 读取结果。 |
| `AVATAR_SECURE_COOKIE` | `0` | 置 `1` 时会话 Cookie 带 `Secure`，仅 HTTPS 部署使用 |

在部署的 `.env` 中可用单引号包住 JSON，例如 `AVATAR_SANDBOX_HTTPS_RESOURCES='{"catalog":"https://data.example.org/catalog.json"}'`。只将示例地址替换为实际授权的公开资源。

管理端“环境信息”在每次创建应用时从实际注册适配器、启动配置、已安装的框架元数据和随包手册位置生成；前端只展示后端返回值。注册模式使用 `AVATAR_PROVIDER`，不另设展示用配置；修改环境或升级依赖后重启生效。通信信息表示启动配置，不代表证书已就绪或端点正在监听。

版本统一由 `application_version()` 读取，环境值会去掉首尾空白。它不改变 wheel 的发行版本，也不覆盖已有 ACS/证书；修改已发布的平台 ACS 仍须遵循身份维护与重新注册流程。

运行后端测试或浏览器验收须在测试进程单独设置 `TEST_POSTGRES_URL`，连接可创建 schema 的专用测试库。示例与清理范围见[测试隔离](PostgreSQL运行.md#开发与测试隔离)。

## OIDC / Keycloak

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `AVATAR_OIDC_ENABLED` | `0` | 是否启用 Keycloak 登录 |
| `AVATAR_OIDC_ISSUER` | `空` | issuer；与 `sub` 共同唯一确定一个账号 |
| `AVATAR_OIDC_CLIENT_ID` | `personal-avatar` | 客户端 ID |
| `AVATAR_OIDC_CLIENT_SECRET` | 空 | 机密客户端时使用；公开客户端可留空 |

## 模型访问

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `AVATAR_MODEL_PROXY` | 空（`None`） | 模型请求直连建连失败时使用的备用代理；不自动继承 `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` |
| `AVATAR_MODEL_DNS_ALIASES` | `{}` | JSON 对象，域名别名映射，用于内网 DNS 不便的场景 |
| `AVATAR_MEMORY_RECENT_MESSAGES` | `6` | 组装上下文时携带的最近消息条数 |

模型密钥不放在环境变量里，而是按账户保存在数据目录（`data/model-secrets.key` 用于加密存储）。
旧 `AVATAR_MEMORY_THRESHOLD` 已不再读取，应从 `.env` 移除；自动摘要比例在每个用户的模型配置中设置，默认上下文窗口的 60%。

## RAG 自适应资源策略

本次不新增环境变量。管理员通过 `GET/PUT /api/admin/rag-resources` 管理策略，保存于 主库 `settings` 的 `rag_resource_policy`；管理端平台设置也提供同一入口，保存后无需重启。

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `max_cpu_cores` / `max_memory_gib` | 40 / 16 | 应用预算上限，结合进程 CPU 亲和性及祖先 cgroup 限制取更小值 |
| `reserve_memory_gib` / `host_cpu_target` | 12 / 70 | 为共享服务器保留内存、CPU 压力阈值（百分比） |
| `max_jobs` / `query_reserved` | 40 / 4 | 全局工作槽上限与查询保留额度；压力下收缩，空闲时逐步增加 |
| `max_index_per_user` | 10 | 单账户资料与 Soul 索引工作单元合计上限，允许 1～10 |
| `soul_concurrency` | 4 | 并行 Soul 构建调度上限，同账户不重复运行构建 |
| `query_concurrency` / `embedding_concurrency` | 16 / 16 | 查询和嵌入阶段上限 |
| `vision_concurrency` / `rerank_concurrency` / `parse_concurrency` | 4 / 8 / 16 | 各阶段工作槽上限；重排序槽仅为后续重排接入预留 |
| `queue_limit` / `query_wait_seconds` | 4096 / 15 | 内存中的工作槽等待者上限、查询等待秒数；不等于 PostgreSQL 持久任务队列容量 |
| `cache_gib` | 8 | 动态缓存预算上限，不超过内存策略的 75%；当前返回预算，尚未将资料向量和模型产物缓存整体改成字节池 |
| `sample_seconds` | 2 | CPU、内存、cgroup 与事件循环压力的采样周期 |
| `enforce_systemd` | false | 默认仅应用内工作槽控制，不是操作系统硬上限。显式开启才尝试为当前服务设置运行时 CPUQuota、MemoryHigh/MemoryMax；没有权限或并非该服务进程时拒绝 |

降低额度不取消已经运行的模型请求，后续任务按新额度准入。软预算不限制其他进程，也不声称约束平台全部 HTTP 请求；本次接入范围是资料索引、Soul、检索向量及资料阅读阶段。关闭硬限制会清除该服务对应的运行时资源属性，父 cgroup 的限制仍然有效。多进程应用各持有一份准入账本，本版按单个服务进程运行；不可把该额度当作跨进程的全局配额。

## 固定额度（代码内约定，非环境变量）

| 项目 | 值 | 说明 |
| --- | --- | --- |
| 资料库容量 | 10 GiB | 每账户上传资料总额度 |
| Soul 直传容量 | 10 GiB | 直接上传进 Soul 的素材；导入不重复占用 |
| 索引工作槽 | 10 | 每账户并行的索引/Soul 素材工作单元上限 |
| 索引重试 | 2 / 5 / 10 秒 | 最多三次额外重试 |
| 模型配置校验超时 | 45 秒 | 保存模型配置前的小规模真实调用 |
| 会话租约上限 | 约 480 秒 | 崩溃窗口内同会话不能续聊的最长等待 |
| 协议确认等待 | 5 分钟 | 超时后后续访问按结算失败处理 |

首次生成 WIT 身份配置需要 `WIT_REGISTRY_URL`、`WIT_CA_URL`、`WIT_REGISTRY_MTLS_URL`，分别指定 Registry、CA 和 Registry mTLS 地址。初始化命令的同名用途参数优先，已有身份继续使用其私有注册文件。小镇 Bearer 认证须设置 `AVATAR_TOWN_OIDC_CLIENT_ID`（与 azp 核对），另行设置允许的 audience。

预设模型通过 `AVATAR_<提供方>_BASE_URL` 覆盖地址。图标、技能归档、模型目录和沙箱安装镜像分别使用 `AVATAR_ICONIFY_HOST`、`AVATAR_GITHUB_ARCHIVE_HOST`、`AVATAR_SILICONFLOW_CATALOG_URL`、`AVATAR_PYODIDE_BASE_URL`；可用提供方及公开默认地址见根目录 .env.example。仅在可信服务之间切换模型端点，现有用户的模型凭据由原平台账户管理。
